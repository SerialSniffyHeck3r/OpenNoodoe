# Content pipeline findings

Official-app runtime analysis distinguished source Creation archives from compiled transmission packages. Compiled packages use a JSON widget graph and named images. This removed the assumption that every theme is a single 480×480 bitmap and explained why a source ZIP cannot be uploaded unchanged.

The gallery path creates a 480×480 quality-80 JPEG and appends the slot byte. A slot-6 upload used chunks 11816, 11816 and 883 bytes. Final DONE took about 6.8 seconds in the observed exchange. These findings informed byte identity and timeout handling.

A generated background-only CFG transferred but lacked a clock/speed widget to classify the renderer. Import now detects supported widget names. The local template editor replaces the background and selected glyph/bar properties while rebuilding MD5 references.

The 2026-09-03 navigation experiment kept one DATA task alive for repeated metadata and image updates; the dashboard stayed in navigation instead of immediately returning after DONE. Radar creation was recognized, but POI marker/coordinate semantics were only partially distinguished. These protocols remain documented reference rather than released app features.

The public tools create payloads from user-authored inputs. No recovered official themes, private photos, decompiled official implementation or firmware binaries accompany these notes.
